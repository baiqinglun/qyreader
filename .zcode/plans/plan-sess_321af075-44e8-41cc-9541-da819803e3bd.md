## 三、核心数据流
1. **导入（M0）**：file_picker 选文件 → 流式 SHA-256 → 魔数嗅探 → 复制进应用私有目录 → isolate 解析（container.xml→OPF→元数据/封面/spine/nav 目录）→ 事务写 books/chapters + 同事务追加 sync_ops → 书架流式刷新。`file_sha256` 重复 → 跳过并提示「已在书架」。
2. **阅读（M1）**：打开书 → 原生外壳 + WebView 加载 reader.html → `init` 注入主题 → JS 回 `ready/relocated` → 进度以 Locator JSON（CFI 主定位 + 章节偏移兜底）落 reading_progress；翻页手势原生接管，双 WebView 池。
3. **标注（M2）**：JS `selection{cfiRange,text,rects}` → 原生工具栏（坐标来自 rects）→ 写 annotations（含冗余 quoted_text + sync_ops）→ `addMark` 高亮层回显；EPUB 正文入 book_fts 支持全书搜索。
4. **同步（M4）**：后台同步器取 `sync_ops where uploaded_at is null` → 写 `devices/{deviceId}/ops/{a}-{b}.jsonl` → 更新自己 manifest（单设备只写自己目录，无全局 manifest）；拉取 LIST devices/ 逐设备比对游标 → 按 HLC 序应用（op_id 幂等）→ 合并规则按文档 6.3（进度 LWW、最远进度 max、标注墓碑并集）。M4 先用 LocalObjectStore 全链路跑通，再接真 S3（届时需你提供仅该前缀读写的密钥）。

## 四、里程碑路线（一次只做一个，做完停等验收）
M0 骨架+导入+书架 → M1 阅读器 → M2 标注 → M3 TTS → M4 同步 → M5 统计/设置/仿真翻页/打磨 → M6 测试打包。**本次批准后只执行 M0。**

## 六、风险点与对策
1. **flutter_inappwebview 对 Windows 桌面支持不明**（疑似仅实验性，FIXME 需核对）→ M1 起正文功能只在 Android 验证；Windows 仅迭代纯 Flutter 页面。
2. **epub.js 0.3.x 老旧** → 自托管锁版本 + 桥协议解耦，必要时仅替换 JS 侧。
3. **包版本漂移**（文档写于 Riverpod 2 时代，2026 年生态可能已到 3.x）→ 锁 2.x 系最新；如与 Flutter 3.32 不兼容再向你报告取舍。
4. **CFI 跨版本不稳定** → Locator 双定位（CFI + 章节偏移）自动降级。
5. **iOS 构建本机不可验证**（无 macOS）→ 保留 ios/ 工程并规避平台专属 API，iOS 验证推迟到有 Mac 时。
6. **S3 凭证安全** → M4 才接入；凭证只进 flutter_secure_storage，日志脱敏。
7. **Android SDK/设备未知** → M0 第一步 `flutter doctor` 出报告，缺什么先补什么，阻塞则停下告诉你。
